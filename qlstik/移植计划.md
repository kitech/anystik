# qlstik 移植计划

> 权威规划文档。目标：`anystik`（QSkinny/Quick）业务功能 → Qt Widgets 桌面版 `qlstik`。
> 编译优先级：**Qt3 → Qt4 → Qt6**。
> 参考：`qldox/`→`../doxhttpd/qltox`（Qt3/4/6 范式 + **curl 异步引擎**）、`qlcomp/`（组件库）、`anystik/`（功能与行为基准）。
> 现状核实日期：2026-09-29（`qlstik/`、`stikcommon/` 均为空目录，anystik 侧未改动）。

## 1. 目标与范围

- 产出 `qlstik` 桌面应用，覆盖 anystik 全部桌面功能：贴纸家 / 生成 / 在线包 / 本地包 / 以图搜图 / 预览 / 编辑 / DAV 同步 / 查号 / 查 IP / 日志 / 登录 / 关于 / 设置 / 托盘 / 主题 / 语言 / 通知 / 存储迁移。
- **不移植 Android 专属模块**：`androidutils`、`android_tls_bootstrap`、`shareintentreceiver`、`keepalive`、`phonemonitor`、`phonesmsstatusbar`、`pushhandler`、`pushstatusbar`、`android/`、`build-android.sh` 及 APK 产物。
- 非 UI 逻辑**与 anystik 共用同一份实现**（共享层），不复制、不重写。
- 三套构建共用一个 `qlstik.pro`：`buildqt3.sh`（QTDIR=/opt/qt338sh）→ `buildqt4.sh`（qmake-qt4）→ `buildqt6.sh`（/opt/qt/6.7.3/gcc_64）。

三条 Qt3 专属约束（实测踩坑，已写进代码注释）：

1. **菜单不可重建**：Qt3 `QMenuData::clear()` 会保留旧分隔线 → 改用「构建时记录 id（Qt3）/ QAction*（Qt4+），切换语言时 `changeItem` / `setText` 就地改写」。
2. **顶级菜单要自己建**：`EmbeddedMenuBar::addMenu` 不返回句柄，而 Qt3 `QMenuBar` 无 `setItemText`（只有 `QMenuData::changeItem(id, …)`）→ qlstik 侧自建 `addTopMenu` 捕获 id。
3. **菜单项不能带参数**：Qt3/4 的菜单项回调签名与 QAction 的 int 参数（checked 态）冲突 → 用 qlcomp 的 `LambdaSlot` 把索引带进槽。


## 5. 传输层：qltox curl 异步引擎（重点）

### 5.1 引擎能力盘点（`qldox/eventpoller.h` 401 行 + `.cpp` 341 行）

- `class EventPoller : public QThread`，静态单例：`start()` / `stop()` / `addRequest()`。
- 后端 `curl_multi`：独立泵线程 `curl_multi_poll(20ms)` + 每轮一次 `curl_multi_perform`，**真异步、不阻塞 GUI**。
- 请求体 `HttpRequest{url, method, data, timeoutSec, stallSec, lowSpeedLimit/Time, delayMs, extraHeaders, progress}`。
- 响应体 `HttpResponse{httpCode, curlErrStr, body, headers(map), elapsedMs}`。
- 健壮性已内建：停滞看门狗（boottime，休眠照算）、curl 原生低速中止、进度 100ms 节流 + 实测速率、非阻塞延迟重发队列、`pendingMutex` 保护 GUI↔泵线程交接。
- 跨线程投递范式（`restapi.cpp`）：回调内 `QApplication::postEvent(s_target, ev)`，事件类型用 `compatcore34.h` 的 `EventType34` / `CustomEventBase`（Qt3 可用）。
- Qt3 可用：已在 `qltox.pro` SOURCES/HEADERS（18/39 行）内，且 qltox 有 `build-qt3` 产物。

### 5.2 复用方式（零复制、不改 qltox）

- `stikcommon/qldox.pri` 收录 `$$QLDOX_DIR/eventpoller.cpp` + `eventpoller.h` → **EventPoller 直接编入 q3stik/q6stik**，不新建、不复制。
- qlstik 的 Qt3/4 网络垫片 = **QNAM 兼容面**（`compat/qt3/qnam_*`），其**后端换成 EventPoller**；不再另写 curl 引擎。
- 语义等价映射：`QNetworkAccessManager` ≈ EventPoller（单例）、`QNetworkReply` ≈ 一次 `HttpRequest` + 投递状态机。

### 5.3 QNAM 面 → EventPoller 映射

| QNAM 调用（共享模块实际用到） | EventPoller 侧 |
|---|---|
| `get/head/put/post(url)` | `addRequest(HttpRequest{url, verb, data, timeoutSec, extraHeaders})` |
| `sendCustomRequest` | 同上，`method` 传自定义 verb |
| `QNetworkRequest::setUrl/setRawHeader/setAttribute` | `HttpRequest.url` / `extraHeaders`（header 走 map） |
| `setTransferTimeout` | `HttpRequest.timeoutSec` |
| `reply->finished/readyRead` | `done` 回调 → `postEvent` 到 reply 所属线程 → 顺序 emit `readyRead` → `finished` |
| `downloadProgress(recv,total)` | `HttpRequest.progress`（节流已在引擎内） |
| `error()/errorString()` | `HttpResponse.httpCode` / `curlErrStr` 映射到 `NetworkError` |
| `rawHeader/hasRawHeader/header` | `HttpResponse.headers` map 查表 |
| `readAll()` | 句柄内累积 body（引擎回传完整 body；流式场景按需分块） |
| `abort()` | **软取消**（见 5.4-a） |
| `setCookieJar/cookieJar` | **qlstik 侧 cookie jar**（见 5.4-b） |
| `QHttpMultiPart/Part` | 手工拼 body + `Content-Type` 边界（见 5.4-c） |
| 同步惯用法（QNAM + QEventLoop） | 投递后在**本地** QEventLoop 等 `finished`（引擎在独立线程，不阻塞） |

### 5.4 三个必须 qlstik 自行解决的点（不改 qltox）

- **a. 取消**：`addRequest` 返回 void、无句柄取消 API → 软取消：`udata` 内放 `QCancelToken{atomic<bool>}`；`abort()` 立即置位并在本地线程 emit `aborted` + `finished`，句柄在 `done` 回调到达时自行销毁并静默丢弃数据（不重复 emit）。
- **b. Cookie**：`HttpRequest` 无 cookie 透传字段 → shim 内维护 `QNetworkCookieJar` 兼容类：请求前把 jar 中匹配 URL 的 cookie 拼成 `Cookie:` 头；响应后从 `headers` 里取 `Set-Cookie` 写回 jar。davbisync 依赖会话 cookie，此项**必须做对**。
- **c. multipart 上传**：`imagetmpuploader` 用 QHttpMultiPart → shim 侧 `QHttpMultiPart/QHttpPart` 拼 body 与边界头，`HttpRequest.data` 承载。
- 另：`readAll()` 一次性返回完整 body（引擎语义），大文件下载走 `progress` + 落盘回调，避免整包驻留。

### 5.5 生命周期与链接

- `main()`：`EventPoller::start()`；`qApp` aboutToQuit → `EventPoller::stop()`。
- `LIBS += -lcurl`（`curl_multi_poll` 需 libcurl ≥ 7.66，脚本里用 `curl-config --version` 校验）；`unix:!macx: -lX11`；`-ldl`；FreeType 走 pkg-config（emoji）。
- Qt3 分支照 `qltox.pro`：`isEmpty(QT_VERSION)` → `DEFINES += QT3_BUILD` + 手工 `QTDIR` 推导。

### 6.2 垫片的引入方式：显式条件 include（无聚合头、无 qt3camel）

- **不建** `qtcompat.h` 聚合头，**不做** `-include` 全局预包含，**不建** qt3camel 式软链映射。
- qlcomp 自身已是 Qt3 干净形态（`compat34.h` / `compatcore34.h` 全部走 `#ifdef QT3_BUILD` 小写头分支），所以壳层与 qltox 的 `cJSON` / `eventpoller` 在 Qt3 下零垫片可编。
- 垫片头放在 `qlstik/compat/{qt3,shared}/`，**由共享模块文件自己的条件 include 引入**（属 §7 允许的「include / #ifdef ≤3 行/文件」改动）：

```cpp
// 共享模块内的标准写法（anystik 侧永远走不到 #else 分支）
#include "compat34.h"                 // qlcomp；Qt3 分支给 Qt3 小写头
#if QT_VERSION >= 0x050000
#include <QJsonDocument>              // Qt5/6 原生
#else
#include "shared/qjson_shim.h"        // qlstik 垫片（QLJSON 家族走 cJSON）
#endif
```

- 阈值约束：单个共享模块的条件 include 改造总计 ≤3 行/文件；超出即触发 §7 的「不可共享」判定。
- `QLNAM` 家族（Qt3 无）在 qlstik 侧落到 `compat/qt3/qnam_shim.h`，后端是 qldox `EventPoller`（§5）。
- 垫片只在 qlstik 构建的 INCLUDEPATH 内可见，anystik 构建不引用，**共享模块两侧行为完全一致**。

### 6.3 垫片收尾项

- `qjson_shim` 的 `utf8Of()` 递归残局（Qt3 分支被误改成自调用）；Qt3 侧 `QVariant::Char`、`QValueList::at()` 语义、`QByteArray` 字符指针构造。
- QNAM shim 三个自解决点（§5.4）与 cookie 往返用例。
- 所有垫片必须在 Qt3 / Qt4 / Qt6 三套下同时不回归。

## 7. 可共享判定标准（阈值）

| 改动类型 | 允许上限 | 超限判定 |
|---|---|---|
| include / `#ifdef` 平台包裹 | ≤3 行/文件 | — |
| latin1 字面量 → `u'x'` / `QChar` / `QString::fromUtf8` | ≤50 行/文件且无语义改动 | 超出或触及逻辑 → 不可共享 |
| 控制流 / 数据结构 / 算法 / 错误处理 | **0 行** | 任意 1 行 → 不可共享 |

按此 `stickerstore` = 3 行 include + 40 行 latin1 = 43 行 → 判可共享。

## 8. 批次迁移（每批 = 一次你编译的节点）

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| EventPoller 无取消 / Cookie / multipart 能力 | §5.4 三项 qlstik 侧自解决，全部只读复用引擎 |
| 引擎回调在泵线程，QNAM 语义要求对象线程 | 统一 `postEvent` + `CustomEventBase`（qltox 既有范式） |
| 垫片层膨胀 | 聚合头单点管理；每批只允许 ≤阈值改动，越线即判不可共享 |
